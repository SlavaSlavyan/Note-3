# Описание базы данных

База данных предназначена для работы автосервиса. Она хранит информацию о клиентах и их автомобилях, доступных услугах, заказах на обслуживание и услугах, включённых в каждый заказ.

В базе данных 5 таблиц: `customers, vehicles, services, work_orders, order_services`.

```text
1. Таблица customers — Клиенты
Хранит информацию о людях, которые пользуются услугами автосервиса.
Столбец			Тип данных	Значение
customer_id		INTEGER		Уникальный идентификатор клиента. Генерируется автоматически. Первичный ключ.
first_name		VARCHAR(50)	Имя клиента.
last_name		VARCHAR(50)	Фамилия клиента.
phone			VARCHAR(25)	Номер телефона клиента. Может отсутствовать.
email			VARCHAR(120)	Адрес электронной почты. Не может повторяться у разных клиентов, но может отсутствовать.
registration_date	DATE		Дата регистрации клиента в системе. По умолчанию используется текущая дата.
status			VARCHAR(20)	Статус клиента: active — активный, inactive — неактивный. По умолчанию active.

2. Таблица vehicles — Автомобили
Хранит автомобили, принадлежащие клиентам. Один клиент может иметь несколько автомобилей.

Столбец		Тип данных	Значение
vehicle_id	INTEGER		Уникальный идентификатор автомобиля. Генерируется автоматически. Первичный ключ.
customer_id	INTEGER		Идентификатор владельца автомобиля. Внешний ключ на customers.customer_id.
make		VARCHAR(50)	Марка автомобиля, например Toyota, Kia или Skoda.
model		VARCHAR(50)	Модель автомобиля, например Corolla или Rio.
production_year	INTEGER		Год выпуска автомобиля. Допустимы значения от 1950 до 2100.
plate_number	VARCHAR(15)	Регистрационный номер автомобиля. Должен быть уникальным.

Важный момент: customer_id — это не идентификатор самого автомобиля, а ссылка на его владельца. Благодаря ему можно получить информацию о владельце через JOIN.
Например, можно вывести все автомобили конкретного клиента, найти машины заданной марки или удалить автомобиль по vehicle_id.

3. Таблица services — Услуги автосервиса
Хранит перечень услуг, которые предлагает автосервис, их стоимость и продолжительность.

Столбец			Тип данных	Значение
service_id		INTEGER		Уникальный идентификатор услуги. Генерируется автоматически. Первичный ключ.
service_name		VARCHAR(100)	Название услуги. Например, «Диагностика» или «Замена масла». Не может повторяться.
price			NUMERIC(10, 2)	Текущая стоимость услуги. Не может быть отрицательной. Например, 2500.00.
duration_minutes	INTEGER		Продолжительность выполнения услуги в минутах. Должна быть больше нуля.

Здесь каждая запись — отдельная услуга, которую можно добавить в заказ на обслуживание.
Обрати внимание: price — это текущая цена услуги в прайс-листе. Если впоследствии стоимость услуги изменится, это не должно автоматически менять стоимость уже оформленных заказов.

4. Таблица work_orders — Заказы на обслуживание
Хранит заказы на обслуживание автомобилей. Каждый заказ связан с одним автомобилем, но у автомобиля может быть несколько заказов.

Столбец		Тип данных	Значение
order_id	INTEGER		Уникальный идентификатор заказа. Генерируется автоматически. Первичный ключ.
vehicle_id	INTEGER		Идентификатор обслуживаемого автомобиля. Внешний ключ на vehicles.vehicle_id.
order_date	TIMESTAMP	Дата и время создания заказа. По умолчанию устанавливаются текущие дата и время.
status		VARCHAR(20)	Статус заказа: new — новый, in_progress — в процессе выполнения, completed — завершён, cancelled — отменён. По умолчанию new.
description	TEXT		Описание заказа или причина обращения, например «Замена масла». Может отсутствовать.

Например, заказ с order_id = 1 относится к автомобилю с vehicle_id = 1.
При этом в таблице хранится не имя клиента и не модель автомобиля, а ссылка на автомобиль. Чтобы вывести информацию о заказе вместе с маркой и моделью машины, нужно соединить таблицы work_orders и vehicles.
Чтобы получить также имя владельца, понадобится соединить и таблицу customers.
С этой таблицей можно создавать и удалять заказы, менять их статус и получать все заказы определённого клиента.

5. Таблица order_services — Услуги внутри заказа
Это связующая таблица между заказами и услугами.
Зачем она нужна? Один заказ может включать несколько услуг, а одна и та же услуга может встречаться во множестве разных заказов.

Например, в заказ могут одновременно входить диагностика, замена масла и шиномонтаж. Хранить все эти услуги в одном столбце таблицы work_orders неудобно, поэтому каждая услуга в заказе оформляется отдельной записью.
Столбец			Тип данных	Значение
order_service_id	INTEGER		Уникальный идентификатор записи об услуге в заказе. Генерируется автоматически. Первичный ключ.
order_id		INTEGER		Идентификатор заказа. Внешний ключ на work_orders.order_id.
service_id		INTEGER		Идентификатор услуги. Внешний ключ на services.service_id.
quantity		INTEGER		Количество единиц услуги. По умолчанию 1, должно быть больше нуля.
unit_price		NUMERIC(10, 2)	Цена одной единицы услуги на момент добавления в заказ. Не может быть отрицательной.

Для отдельной строки стоимость вычисляется так: quantity * unit_price
А общая стоимость заказа — как сумма стоимостей всех его строк.
```
