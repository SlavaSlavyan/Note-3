# Практическая работа: система продажи билетов в кинотеатр

**Технологии:** C#, ADO.NET, PostgreSQL, Npgsql  
**Формат:** консольное приложение

## 1. Цель работы

Разработать консольное приложение для работы с учебной базой данных кинотеатра. Приложение должно показывать фильмы и сеансы, находить свободные места, оформлять и отменять покупку билетов, а также формировать отчёты.

В работе необходимо использовать основные средства ADO.NET: `NpgsqlConnection`, `NpgsqlCommand`, параметры SQL-команд, `NpgsqlDataReader`, скалярные запросы и транзакции. ORM (например, Entity Framework) использовать нельзя.

## 2. Подготовка базы данных

1. В PostgreSQL создайте отдельную пустую базу данных с именем `cinema_training`.
2. Подключитесь к ней в pgAdmin или другом SQL-клиенте.
3. Выполните скрипт `cinema_training.sql`. **Скрипт удаляет и пересоздаёт одноимённые таблицы**, поэтому запускайте его только в учебной базе.
4. Создайте консольный проект .NET и установите драйвер:

```bash
dotnet new console -n CinemaAdoNet
dotnet add CinemaAdoNet package Npgsql
```

5. Настройте строку подключения к своей БД. Пример формата:

```text
Host=localhost;Port=5432;Database=cinema_training;Username=postgres;Password=ВАШ_ПАРОЛЬ
```

Не публикуйте реальный пароль в репозитории.

## 3. Что хранится в базе

| Таблица | Назначение |
|---|---|
| `films` | Фильмы: название, жанр, длительность, возрастной рейтинг, год выпуска |
| `halls` | Залы кинотеатра и количество мест |
| `seats` | Места внутри залов; уникальный номер места в пределах зала |
| `screenings` | Сеансы: фильм, зал, дата и время, цена билета |
| `customers` | Клиенты кинотеатра |
| `tickets` | Билеты, место, сеанс, покупатель, статус и время покупки |

У билета статус `Purchased` означает действующий купленный билет, `Cancelled` — отменённый. Отменённые билеты остаются в таблице как история. Одно место на одном сеансе не может иметь два действующих билета.

## 4. Требования к приложению

Сделайте меню, позволяющее выбирать операции. После выполнения операции программа должна возвращаться в меню, пока пользователь не выберет выход.

### Задание 1. Подключение к БД

- Открыть подключение к PostgreSQL с помощью `NpgsqlConnection`.
- При запуске проверить, что подключение работает, выполнив простой запрос, например `SELECT CURRENT_TIMESTAMP`.
- Вывести понятное сообщение об успешном подключении.
- Корректно обработать ошибку подключения. Соединения и команды должны освобождаться через `using` / `await using`.

### Задание 2. Просмотр фильмов

Вывести список фильмов: идентификатор, название, жанр, длительность, возрастной рейтинг и год выпуска.

Дополнительно реализовать поиск фильма по части названия. Строку поиска передавать в SQL **через параметр**, например с оператором `ILIKE`.

### Задание 3. Расписание и свободные места

Вывести список сеансов. Для каждого сеанса показать:

- идентификатор сеанса;
- название фильма и жанр;
- дату и время начала;
- название зала;
- цену одного билета;
- общее количество мест;
- количество свободных мест.

Результат должен быть получен SQL-запросом с объединением связанных таблиц (`JOIN`) и подсчётом мест. Отменённые билеты не должны считаться занятыми.

Предусмотреть фильтрацию сеансов по выбранной дате или диапазону дат. Значения фильтра передавать параметрами SQL-команды.

### Задание 4. Поиск клиента и его билетов

Пользователь вводит адрес электронной почты клиента. Приложение должно найти клиента и вывести его билеты: название фильма, время сеанса, зал, номер места, цену и статус билета.

Если клиент не найден, вывести понятное сообщение, а не завершать программу с ошибкой.

### Задание 5. Регистрация клиента

Реализовать добавление клиента с вводом имени, фамилии, email и телефона.

- Не допускать пустые обязательные поля.
- Использовать параметризованный `INSERT`.
- Получить идентификатор добавленного клиента с помощью `RETURNING customer_id` и вывести его на экран.
- Обработать ситуацию, когда email уже существует.

### Задание 6. Покупка билета

Реализовать оформление билета по идентификаторам сеанса и клиента, а также по номеру места.

Алгоритм операции:

1. Проверить, существуют ли выбранные сеанс и клиент.
2. Убедиться, что номер места существует в зале выбранного сеанса.
3. Проверить, что место свободно: на этом сеансе нет билета со статусом `Purchased` на это место.
4. Добавить билет со статусом `Purchased`.
5. Показать подтверждение покупки с номером билета, названием фильма, датой сеанса, местом и ценой.

Оформление должно быть защищено от ситуации, когда два пользователя одновременно пытаются купить одно место. Для этого:

- выполнять связанные действия в транзакции (`BeginTransaction`);
- передавать транзакцию всем командам, участвующим в операции;
- учитывать, что уникальный индекс в БД может отклонить повторную покупку даже после предварительной проверки;
- при успехе выполнять `Commit`, при ошибке — `Rollback`;
- перехватывать ожидаемую ошибку нарушения уникальности и сообщать, что место уже занято.

### Задание 7. Отмена билета

По номеру билета отменить действующий билет, изменив его статус на `Cancelled`. Физически удалять строку из `tickets` нельзя: запись нужна для истории.

Если билет не существует или уже отменён, вывести соответствующее сообщение. Проверять результат `UPDATE` по количеству изменённых строк (`ExecuteNonQuery`). После отмены место должно снова отображаться как свободное.

### Задание 8. Отчёт по сеансам

Вывести отчёт по каждому сеансу, содержащий название фильма, дату и время, зал, число проданных билетов и выручку.

Требования к расчёту:

- учитывать только билеты со статусом `Purchased`;
- использовать агрегатные функции, например `COUNT` и `SUM`, и группировку `GROUP BY`;
- сеансы без продаж тоже должны присутствовать в отчёте;
- денежные значения не переводить в `double` без необходимости: учитывать тип `numeric` PostgreSQL и тип `decimal` в C#.

Дополнительно вывести топ-3 фильма по количеству проданных билетов.

## 5. Технические требования ADO.NET

1. Использовать `NpgsqlConnection` для подключения к PostgreSQL.
2. Для запросов применять `NpgsqlCommand`.
3. Для всех значений, введённых пользователем, использовать параметры (`Parameters.AddWithValue` или типизированные параметры). Не подставлять пользовательский ввод в SQL через конкатенацию или интерполяцию строк.
4. Для выборок с несколькими строками использовать `NpgsqlDataReader`.
5. Для одиночного значения при необходимости применять `ExecuteScalar`.
6. Для `INSERT`, `UPDATE` и `DELETE` использовать `ExecuteNonQuery`, кроме запросов, возвращающих значение через `RETURNING`.
7. Использовать `using` / `await using` для освобождения ресурсов.
8. Обрабатывать ошибки подключения и ожидаемые ошибки БД. Сообщения для пользователя должны быть понятными; технические детали можно выводить отдельно для разработчика.
9. Разделить код хотя бы на методы по операциям меню. Не размещать всю программу в одном длинном блоке кода.
10. Запросы должны выполняться в PostgreSQL; запрещено загружать все таблицы в память и выполнять всю фильтрацию только средствами C#.
