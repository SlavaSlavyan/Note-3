### Объектно-реляционное преображение
C# данные обычно представлены объектами, классами, свойствами и коллекциями. Между объектной и реляционной моделью существует различие. Объект содержит свойства и поведения, А строка таблицы значение столбцов, ограничения и связь

ORM(Object Relational Mapping) Объектно-реляционное отображение - подход, при котором библиотека связывает классы приложения с таблицами или другими структурами баз данных, а свойства объектов со столбцами. ORM формирует SQL, передает команды провайдеру БД и преобразует результаты запросов в объекты

Entity Framework Core(EF) - кроссплатформенный ORM Framework для ADO.NET. Он предоставляет объектную модель для доступа к данным.  LINQ Запросы, отслеживание изменений, сохранение объектов, настройку сопоставления сущностей и механизм миграции.

EF не является СУБД и не хранит данные самостоятельно. Фактическое хранение, выполнение SQL, блокировки, индексы, ограничения целостности и транзакции обеспечивает PostgreSQL. EF Core реализует взаимодействие с провайдером БД
![[Pasted image 20261020094946.png]]
 Главное различие. ADO.NET предоставляет низко-уровневые строительные блоки для доступа к данным. EF Core предоставляет более высокий уровень абстракции, работу с объектной моделью. EF Core не отменяет SQL, он генерирует SQL для многих операций, а разработчик должен понимать какой запрос получится и на сколько он эффективен.    

## Преимущества и ограничения ORM
Преимущества:
меньше повтор. кода
автомат. отображение строк на объекты
единый подход к чтению и изменению данных
LINQ с проверками типов компилятора
Управление связями и миграциями
Ограничения:
не каждый c# метод переводится в SQL
Сгенерированный запрос может быть не эффективен
Отслеживание потребляет память
Модель может не совпадать с существующей схемой

EF Core часто удобен для CRUD приложения, административных интерфейсов, сервисов с большим кол-вом связанных сущностей и приложений, где важно сопровождать объектную модель. Прямой SQL может быть уместнее для специализированных запросов, сложных отчетов, процедур с точным контролем SQL или сценариев, где требуется минимальная ORM абстракция. В одном проекту допустимо сочетать EF Core и прямой SQL, соблюдая единое правило транзакций и владение соединениями

Основные компоненты EF Core:
Entity(Сущность) - класс предметной области, экземпляры которого обычно отображаются на записи реляционной таблицы
Model - описание сущностей, ключей, типов, ограничений и отношений используемых EF Core
DbContext - предоставляет короткую единицу работы с базой: конфигурацию, запросы, отслеживаемые сущности и сохранение изменений
DbSet<TEntity> - точка доступа в сущности одного типа обычно соответствуют наборы записи таблицы.
Provider - компонент, который адаптирует EF Core в конкретной СУБД
Change Tracker - компонент контекста, который отслеживает экземпляры сущностей и их состояния
Драйвер БД - компонент реализации взаимодействия с сервером БД

Миграции БД - это версионированные изменение структуры(схемы) БД, которые хранятся в виде отдельных файлов/скриптов и применяются последовательно для перевода БД из одного состояния в другое

LINQ(Language Integrated Query) - синтаксис и набор API .NET для формирования запросов к различным источникам данных
Миграция — версионированное описание изменения схемы: создание таблицы, добавление столбца, создание индекса или изменение отношения. Команда migrations add сравнивает текущую модель с сохранённым снимком предыдущего состояния модели и генерирует код миграции. Команда database update применяет не применённые миграции к базе и записывает сведения о них в служебную таблицу истории. Файлы миграций следует хранить в системе контроля версий.
Миграция — не просто автоматическое обновление классов, а сценарий изменения схемы. Его необходимо проверять, особенно при переименовании или удалении столбцов. Неудачная конфигурация может привести к потере данных или несовместимости с текущей базой.
