## 1. Что такое класс

**Класс** — это шаблон (чертёж) для создания объектов. Он описывает, какие данные (поля) будут у объекта и какие действия (методы) он умеет выполнять.

Представь, что класс — это чертёж дома, а объект — это сам дом. По одному чертежу можно построить сколько угодно домов, и у каждого будут свои особенности (цвет стен, жильцы), но структура одинаковая.

**Класс = поля (данные) + методы (поведение)**

Пример:
```java
public class Student {
    // Поля (данные)
    String name;
    int age;
    double grade;

    // Методы (поведение)
    void study() {
        System.out.println(name + " учится");
    }
}
```

Здесь `Student` — это класс. Он описывает, что у любого студента есть имя, возраст, оценка и что студент умеет учиться.

## 2. Зачем нужны классы

Без классов программа — это набор разрозненных переменных и функций.

Пример без класса:
```java
// Без класса — данные «размазаны» по коду
String student1Name = "Аня";
int student1Age = 20;
double student1Grade = 4.5;

String student2Name = "Иван";
int student2Age = 22;
double student2Grade = 3.8;
```

**Проблемы:**
1. Данные одного студента не связаны — легко перепутать.
2. Чтобы передать студента в функцию — нужно передавать 3 параметра.
3. Нет способа сказать «этот набор данных — единое целое».

Тот же пример, но с классом:
```java
Student s1 = new Student("Аня", 20, 4.5);
Student s2 = new Student("Иван", 22, 3.8);
```

**Преимущества:**
1. Данные объединены — один объект = один студент.
2. Переиспользование — один класс → много объектов.
3. Читаемость — `s1.getName()` понятнее, чем `student1Name`.
4. Инкапсуляция — можно скрыть внутреннее устройство.
5. Код читабельнее.

## 3. Отличие класса от метода

| | Класс | Метод |
|---|---|---|
| **Что это** | Шаблон для создания объектов | Действие (поведение) объекта или класса |
| **Что содержит в себе** | Поля, методы, конструкторы | Инструкции (код), выполняемые при вызове |
| **Как лучше называть** | Имя существительное, с большой буквы (`Student`) | Глагол, с маленькой буквы (`study`) |
| **Синтаксис** | `class Student { ... }` | `void study() { ... }` |
| **Где живёт** | В отдельном файле (обычно) | Внутри класса |
| **Пример** | `public class Student { ... }` | `public void study() { ... }` |

## 4. Основные элементы класса

1. **Поля** — данные объекта
```java
class Person {
    String name;          // поле
    int age;              // поле
    private double salary; // поле с модификатором
}
```

2. **Методы** — поведение
```java
class Person {
    // метод
    void greet() {
        System.out.println("Привет, я " + name);
    }
}
```

3. **Конструктор** — создание объекта
```java
class Person {
    String name;
    int age;

    // Конструктор
    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

**Конструктор:**
- Называется как класс.
- Нет возвращаемого типа (даже `void`).
- Вызывается при `new`.
- Если не написать — Java создаст пустой по умолчанию.

## 4. Модификаторы доступа

**Что это такое:** ключевые слова, которые определяют, откуда можно обращаться к полям, методам и конструкторам класса.

**Виды и видимость:**

| Модификатор | Видимость |
|---|---|
| `private` | Только внутри этого класса |
| *(без модификатора)* `default` | Внутри пакета |
| `protected` | Внутри пакета и в подклассах |
| `public` | Отовсюду |

**Для чего используют:** чтобы скрыть внутреннюю реализацию (инкапсуляция) и предоставить безопасный доступ через методы. Чаще всего поля делают `private`, а методы — `public`.

**Пример:**
```java
public class Person {
    private String name;   // скрыто от внешнего мира
    public int age;        // доступно отовсюду

    public String getName() { // public-метод для доступа к private-полю
        return name;
    }
}
```

## 5. `static` и `static final`

**Что это такое:**
- `static` — модификатор, означающий, что поле или метод принадлежит самому классу, а не конкретному объекту. Такие члены называются статическими.
- `static final` — статическая константа: значение задаётся один раз и не может быть изменено.

**Зачем нужно:**
- `static` позволяет иметь общие данные для всех объектов класса (например, счётчик созданных объектов) или утилитные методы, которые не зависят от состояния объекта.
- `static final` используется для констант (например, `Math.PI`), чтобы значение было единым для всех и защищено от изменения.

**Для чего применяется:** счётчики, константы, фабричные методы, вспомогательные функции.

**Пример:**
```java
public class Counter {
    private static int count = 0;          // общее для всех объектов
    public static final double PI = 3.14;  // константа

    public Counter() {
        count++; // увеличиваем общий счётчик при создании объекта
    }

    public static int getCount() { // статический метод
        return count;
    }
}
```
Здесь `count` — один на весь класс `Counter`, а `PI` — неизменяемая константа. Обращение: `Counter.getCount()`, `Counter.PI`.

## 6. `this`

**Что это такое:** ссылка на текущий объект, внутри которого выполняется метод или конструктор.

**Зачем нужно:** чтобы различать поля класса и параметры методов/конструкторов с одинаковыми именами, а также чтобы вызывать другие конструкторы или методы текущего объекта.

**Для чего применяется:** в конструкторах (`this.name = name`), для передачи текущего объекта в другие методы, для вызова цепочки конструкторов (`this()`).

**Пример:**
```java
public class Person {
    private String name;

    public Person(String name) {
        this.name = name; // this.name — поле, name — параметр
    }

    public void setName(String name) {
        this.name = name; // без this было бы присваивание параметра самому себе
    }
}
```
Без `this` в `this.name = name` левая часть означала бы параметр, и поле не изменилось бы.

## 7. Инкапсуляция, геттеры и сеттеры

**Что это такое:**
- **Инкапсуляция** — принцип скрытия внутреннего состояния объекта и предоставления доступа к нему только через специальные методы.
- **Геттер** — метод для получения значения поля (`getName()`).
- **Сеттер** — метод для установки значения поля (`setName()`).

**Зачем нужно:** защитить данные от некорректного изменения, скрыть детали реализации, обеспечить контролируемый доступ.

**Для чего применяется:** поля делают `private`, а для доступа создают `public` геттеры и сеттеры. В сеттере можно добавить проверку (валидацию).

**Пример:**
```java
public class Person {
    private String name;
    private int age;

    // Геттер
    public String getName() {
        return name;
    }

    // Сеттер
    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        }
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age > 0) {
            this.age = age;
        }
    }
}
```

**Отличие геттера от сеттера:**
- Геттер только возвращает значение поля, ничего не меняет.
- Сеттер изменяет значение поля, может содержать проверки.

## 8. Методы: `toString()`, `equals()`, `hashCode()`

**Что это такое:** переопределяемые методы класса `Object`, которые задают строковое представление объекта, логическое сравнение и хеш-код.

**Зачем нужно:**
- `toString()` — чтобы получить читаемое строковое представление объекта (удобно для вывода).
- `equals()` — чтобы сравнивать объекты по содержимому, а не по ссылке.
- `hashCode()` — чтобы объекты корректно работали в хеш-коллекциях (`HashMap`, `HashSet`).

**Для чего применяется:** при выводе объектов, сравнении, использовании в коллекциях.

**Пример:**
```java
public class Person {
    private String name;
    private int age;

    // ... конструктор и геттеры/сеттеры ...

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Person person = (Person) o;
        return age == person.age && Objects.equals(name, person.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}
```
- `toString()` возвращает строку с данными объекта.
- `equals()` сравнивает два объекта по полям `name` и `age`.
- `hashCode()` вычисляет хеш на основе тех же полей, что и `equals()`, — это важно для корректной работы коллекций.

## Шаблон класса

```java
public class ИмяКласса {
    // 1. Поля
    private тип поле1;
    private тип поле2;

    // 2. Конструктор
    public ИмяКласса(тип поле1, тип поле2) {
        this.поле1 = поле1;
        this.поле2 = поле2;
    }

    // 3. Геттеры
    public тип getПоле1() { return поле1; }
    public тип getПоле2() { return поле2; }

    // 4. Сеттеры
    public void setПоле1(тип поле1) { this.поле1 = поле1; }
    public void setПоле2(тип поле2) { this.поле2 = поле2; }

    // 5. Методы
    public тип метод() {
        // ...
    }

    // 6. toString
    @Override
    public String toString() {
        return "ИмяКласса{поле1=" + поле1 + ", поле2=" + поле2 + "}";
    }
}
```
