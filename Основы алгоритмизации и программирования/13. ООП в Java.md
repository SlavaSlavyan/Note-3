Объектно-ориентированное программирование (ООП) — это не просто синтаксис, а способ мышления о программе как о совокупности взаимодействующих объектов.

---
## История развития ООП (по этапам)

Концепция ООП не появилась вместе с Java. Java вобрала в себя идеи, развивавшиеся десятилетиями, и добавила к ним строгую статическую типизацию и кроссплатформенность.

| Этап       | Ключевое событие                                                                                                                                                                                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1960-е** | **Simula 67** (Оле-Йохан Даль, Кристен Нюгор) — первый язык с классами, объектами и наследованием. Идеи Simula заложили фундамент парадигмы.                                                                                                                                                                                                  |
| **1970-е** | **Smalltalk** (Алан Кэй, Xerox PARC) — язык, в котором ООП стало основной парадигмой, а не надстройкой. Именно там появились понятия «сообщений» и «методов» в их современном виде.                                                                                                                                                           |
| **1980-е** | **C++** (Бьёрн Страуструп) — привнёс ООП в мир системного программирования, объединив его с производительностью C.                                                                                                                                                                                                                            |
| **1995**   | **Java** (Джеймс Гослинг, Sun Microsystems) — с самого начала проектировалась как объектно-ориентированный язык. В отличие от C++, Java сделала ООП более строгим и безопасным: «всё является объектом» (кроме примитивных типов), множественное наследование заменено интерфейсами, а сборка мусора сняла с программиста управление памятью. |
| **2004**   | **Java 5** — добавила параметризованные типы (generics), которые усилили типобезопасность при работе с коллекциями объектов.                                                                                                                                                                                                                  |
| **2014**   | **Java 8** — привнесла лямбда-выражения и методы по умолчанию в интерфейсах, сделав функциональный стиль частью объектной модели.                                                                                                                                                                                                             |

## Основные элементы ООП в Java

### 1. Класс

**Что это.** Класс — это шаблон (чертёж), по которому создаются объекты. Он описывает состояние (поля) и поведение (методы) будущих объектов. В Java любая программа представляет собой набор классов, и каждый класс является базовой сущностью ООП.

**Для чего.** Класс позволяет один раз описать структуру и поведение, а затем создавать по этому описанию любое количество независимых объектов.

**Сравнение из жизни.** Класс — это чертёж автомобиля. По одному и тому же чертежу можно собрать сколько угодно машин, и каждая из них будет иметь одинаковую конструкцию, но свой цвет, пробег и номер.

**Шаблон написания (Java):**

```
[модификатор] class ИмяКласса {
    // поля (атрибуты)
    // конструкторы
    // методы
}
```

**Пример:**

```java
public class Car {
    private String model;
    private int year;

    public Car(String model, int year) {
        this.model = model;
        this.year = year;
    }

    public void drive() {
        System.out.println(model + " едет.");
    }
}
```

---

### 2. Объект

**Что это.** Объект — это экземпляр класса. Он обладает собственным набором значений полей и может вызывать методы, определённые в классе.

**Для чего.** Объекты — это «живые» сущности, с которыми программа работает во время выполнения. Именно они хранят состояние и выполняют действия.

**Сравнение из жизни.** Если класс — чертёж, то объект — конкретный автомобиль, стоящий в гараже: у него есть свой цвет, свой VIN-номер и свой пробег.

**Шаблон написания (Java):**

```java
ИмяКласса имяОбъекта = new ИмяКласса(аргументы);
```

**Пример:**

```java
Car myCar = new Car("Toyota", 2022);
myCar.drive(); // Toyota едет.
```

---

### 3. Атрибут (поле)

**Что это.** Атрибут (в Java — **поле**, field) — это именованное свойство класса или объекта. Поле может относиться как к каждому объекту отдельно (нестатическое), так и к классу в целом (статическое).

**Для чего.** Поля хранят состояние объекта. Именно они определяют, чем один объект класса отличается от другого.

**Сравнение из жизни.** Цвет, вес и скорость — это атрибуты автомобиля. У каждого объекта они могут быть разными.

**Шаблон написания (Java):**

```java
[модификатор доступа] [static] [final] тип имяПоля [= значение];
```

**Пример:**

```java
public class Car {
    private String model;          // поле экземпляра
    private int year;              // поле экземпляра
    public static int wheels = 4;  // статическое поле (общее для всех)
    public static final int MAX_SPEED = 220; // константа
}
```

---

### 4. Метод

**Что это.** Метод — это программная функция, привязанная к объекту или классу. Он определяет, что объект умеет делать.

**Для чего.** Методы реализуют поведение: они читают и изменяют поля, выполняют вычисления, взаимодействуют с другими объектами.

**Сравнение из жизни.** У автомобиля есть методы «завестись», «ускориться» и «затормозить». Это действия, которые можно выполнить над объектом.

**Шаблон написания (Java):**

```java
[модификатор доступа] [static] возвращаемыйТип имяМетода(параметры) {
    // тело метода
    [return значение;]
}
```

**Пример:**

```java
public class Car {
    private int speed;

    public void accelerate(int delta) {
        speed += delta;
    }

    public int getSpeed() {
        return speed;
    }
}
```

### 5. Интерфейс

**Что это.** Интерфейс в Java — это контракт, который описывает, **что** класс должен уметь делать, но не **как**. До Java 8 интерфейс содержал только абстрактные методы; начиная с Java 8 в нём появились методы по умолчанию (`default`), а с Java 9 — приватные методы.

**Для чего.** Интерфейс позволяет задать общий набор операций для классов, которые могут быть никак не связаны иерархией наследования. Это способ достичь полиморфизма без жёсткой привязки к конкретному классу.

**Сравнение из жизни.** Интерфейс `Drivable` — это «умение управлять». Совершенно не важно, что это за транспорт: легковая машина, грузовик или автобус. Если объект реализует этот интерфейс, с ним можно обращаться единообразно.

**Ключевое отличие от абстрактного класса (в Java):**

- Абстрактный класс может хранить состояние (поля экземпляра) и описывать часть общего поведения.
- Интерфейс не описывает состояние. Его поля (если они есть) неявно являются `public static final` — то есть константами.
- Класс может наследовать только один абстрактный класс, но реализовывать любое количество интерфейсов.

**Шаблон написания (Java):**

```java
[модификатор] interface ИмяИнтерфейса {
    // константы
    // абстрактные методы
    // default-методы (Java 8+)
    // static-методы (Java 8+)
    // private-методы (Java 9+)
}
```

**Пример:**

```java
public interface Drivable {
    void drive();
    void stop();

    default void honk() {
        System.out.println("Бип!");
    }
}

public class Car implements Drivable {
    @Override
    public void drive() {
        System.out.println("Машина едет.");
    }

    @Override
    public void stop() {
        System.out.println("Машина остановилась.");
    }
}
```

### 6. Конструктор

**Что это.** Конструктор — это специальная структура, предназначенная для создания экземпляра класса и инициализации его полей.

**Для чего.** Конструктор гарантирует, что объект будет создан в корректном начальном состоянии.

**Сравнение из жизни.** Конструктор — это заводская сборка автомобиля: прежде чем машина поедет, её нужно собрать и заправить.

**Что важно знать о конструкторах в Java:**

- Имя конструктора **совпадает** с именем класса.
- Конструктор **не имеет возвращаемого типа** (даже `void`).
- Если конструктор не объявлен явно, компилятор создаёт **конструктор по умолчанию** (без параметров), который вызывает `super()`.
- Конструкторы можно **перегружать**: в одном классе может быть несколько конструкторов с разными параметрами.
- Вызов `this(...)` делегирует выполнение другому конструктору того же класса, а `super(...)` — конструктору родительского класса. Оба вызова должны быть **первой строкой** конструктора.
- Конструктор **не наследуется** и не может быть `abstract`, `final`, `static` или `synchronized`.

**Шаблон написания (Java):**

```java
[модификатор доступа] ИмяКласса(параметры) {
    // инициализация
    // this(...) или super(...) — при необходимости
}
```

**Пример:**

```java
public class Car {
    private String model;
    private int year;

    public Car() {
        this("Unknown", 0);
    }

    public Car(String model, int year) {
        this.model = model;
        this.year = year;
    }
}
```

### 7. Модификаторы доступа

**Что это.** Модификаторы доступа управляют видимостью классов, полей, методов и конструкторов. В Java их четыре (включая отсутствие модификатора, которое тоже является уровнем доступа).

**Для чего.** Модификаторы доступа — это практическая реализация принципа **инкапсуляции**. Они позволяют скрыть внутреннюю реализацию и оставить наружу только то, что действительно нужно другим классам.

**Сравнение из жизни.** Пульт от телевизора: вам доступны кнопки (публичный интерфейс), но внутренняя электроника и провода скрыты в корпусе (приватная реализация).

**Четыре уровня доступа в Java:**

| Модификатор | Класс | Пакет | Подкласс (другой пакет) | Весь мир |
|---|---|---|---|---|
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| *(без модификатора)* `package-private` | ✅ | ✅ | ❌ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

**Шаблон написания (Java):**

```java
public class Example {
    private int privateField;       // только внутри класса
    int packageField;               // внутри пакета (без модификатора)
    protected int protectedField;   // пакет + подклассы
    public int publicField;         // везде
}
```

## Основные принципы ООП в Java

### 1. Инкапсуляция

**Что это.** Инкапсуляция — это сокрытие деталей реализации и предоставление контролируемого доступа к данным через публичный интерфейс. В Java инкапсуляция достигается за счёт `private`-полей и `public`-методов доступа (геттеров и сеттеров).

**Для чего.** Инкапсуляция защищает объект от некорректного внешнего вмешательства и позволяет менять внутреннюю реализацию, не ломая код, который использует этот класс.

**Сравнение из жизни.** Кабина пилота в самолёте: пассажирам не нужно знать, как управлять самолётом. Они взаимодействуют с ним через простой интерфейс — покупают билет и садятся на рейс. Сложная навигация и управление скрыты.

**Ключевое отличие.** Инкапсуляция — это не просто «сделать поле приватным». Это осознанное проектирование границы между **внутренним состоянием** и **внешним контрактом**.

**Шаблон написания (Java):**

```java
public class ИмяКласса {
    private тип поле;

    public тип getПоле() {
        return поле;
    }

    public void setПоле(тип значение) {
        // валидация при необходимости
        this.поле = значение;
    }
}
```

**Пример:**

```java
public class BankAccount {
    private double balance;

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}
```

### 2. Наследование

**Что это.** Наследование — это механизм, позволяющий создать новый класс на основе уже существующего, унаследовав его поля и методы и добавив или переопределив поведение. В Java наследование реализуется с помощью ключевого слова `extends`.

**Для чего.** Наследование устраняет дублирование кода и выстраивает иерархию «общее — частное».

**Сравнение из жизни.** Если нужно создать что-то новое, часто эффективнее взять уже существующее решение и доработать его, чем создавать с нуля. Человек «наследует» многие черты от общего предка, а не изобретает их заново.

**Ключевое отличие.** В Java поддерживается **только одиночное наследование классов** (один родитель). Множественное наследование поведения достигается через интерфейсы.

**Шаблон написания (Java):**

```java
[модификатор] class ДочернийКласс extends РодительскийКласс {
    // дополнительные поля и методы
    // @Override для переопределённых методов
}
```

**Пример:**

```java
public class Vehicle {
    protected int speed;

    public void move() {
        System.out.println("Транспорт движется.");
    }
}

public class Car extends Vehicle {
    @Override
    public void move() {
        System.out.println("Машина едет со скоростью " + speed);
    }
}
```

### 3. Полиморфизм

**Что это.** Полиморфизм — это способность объектов с одинаковым интерфейсом (общим родителем или общим интерфейсом) вести себя по-разному в зависимости от их конкретного типа. В Java полиморфизм достигается через **переопределение методов** (`@Override`) и **позднее связывание** (dynamic dispatch).

**Для чего.** Полиморфизм позволяет писать код, который работает с абстракцией, а не с конкретным типом, что делает программу гибкой и расширяемой.

**Сравнение из жизни.** Человек, умеющий водить машину, может сесть за руль и легкового автомобиля, и грузовика, и скорой помощи. Интерфейс управления у них общий (руль, педали), хотя внутреннее устройство разное.

**Ключевое отличие.** В Java полиморфизм работает через **ссылку на родительский тип или интерфейс**, которая может указывать на объект любого дочернего класса.

**Шаблон написания (Java):**

```java
РодительскийТип объект = new ДочернийКласс();
объект.метод(); // вызовется версия метода из ДочернегоКласса
```

**Пример:**

```java
Drivable d1 = new Car();
Drivable d2 = new Truck();

d1.drive(); // Машина едет.
d2.drive(); // Грузовик едет.
```

### 4. Абстракция

**Что это.** Абстракция — это выделение только тех характеристик объекта, которые существенны для решаемой задачи, и отбрасывание второстепенных. В Java абстракция достигается через **абстрактные классы** (`abstract class`) и **интерфейсы** (`interface`).

**Для чего.** Абстракция позволяет моделировать сложные системы, не увязая в деталях. Программист работает с понятиями «водитель», «транспорт», «платёж», а не с бесконечным множеством конкретных реализаций.

**Сравнение из жизни.** Должность «директор» в компании — это абстракция. Конкретный человек, занимающий эту должность, может меняться, но набор обязанностей и место в структуре остаются. Абстракция позволяет описать роль, не привязываясь к конкретному исполнителю.

**Ключевое отличие.** Абстракция — это **взгляд сверху**: она отвечает на вопрос «что важно в объекте для нашей задачи?», тогда как инкапсуляция отвечает на вопрос «как скрыть реализацию?».

**Шаблон написания (Java):**

```java
// Абстрактный класс
[модификатор] abstract class ИмяКласса {
    // поля
    // конкретные методы
    // абстрактные методы (без тела)
}

// Интерфейс (контракт поведения)
[модификатор] interface ИмяИнтерфейса {
    // абстрактные методы
}
```

**Пример:**

```java
public abstract class Shape {
    public abstract double area();
}

public class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}
```

## Сводная таблица: элементы и принципы в контексте Java

| Понятие | Роль в Java | Ключевой синтаксис |
|---|---|---|
| **Класс** | Шаблон объекта | `class`, `public class` |
| **Объект** | Экземпляр класса | `new` |

| **Абстракция** | Выделение существенного | `abstract class`, `interface` |
