### Языки программирования и их развитие

#### 1. Что такое язык программирования? Чем он отличается от естественного (человеческого) языка?

**Язык программирования** — это формальный набор правил и обозначений, созданный для записи компьютерных программ. Он позволяет человеку описывать алгоритмы, структуры данных и логику работы, которые компьютер должен выполнить. По сути, это посредник между человеческим мышлением и машинным кодом.

**Отличия от естественного языка:**

1.  **Строгость и однозначность:** В программировании нет места метафорам, интонациям или двусмысленности. Каждая команда имеет одно строго определенное значение. В естественном языке фраза «казнить нельзя помиловать» зависит от запятой, в коде ошибка синтаксиса просто не даст программе запуститься.
2.  **Ограниченный словарный запас:** В языках программирования обычно несколько десятков ключевых слов (например, `if`, `for`, `class`), тогда как естественный язык содержит сотни тысяч слов.
3.  **Синтаксис и семантика:** В естественном языке можно переставить слова, и смысл сохранится. В коде нарушение синтаксиса (правил написания) ведет к ошибке компиляции, а нарушение семантики (смысла) — к логической ошибке.
4.  **Цель:** Естественный язык служит для общения между людьми (выражение эмоций, обмен опытом). Язык программирования — для точной передачи инструкций машине.

#### 2. Основные поколения языков программирования

Развитие языков шло по пути упрощения взаимодействия человека с машиной (от сложного к удобному).

1.  **Первое поколение (1GL): Машинные коды.**
    *   **Суть:** Программы состоят из двоичного кода (нулей и единиц), который процессор понимает напрямую.
    *   **Особенности:** Очень быстрые, но писать их чрезвычайно сложно, код привязан к конкретному процессору (непереносим), высокая вероятность ошибок.
2.  **Второе поколение (2GL): Языки Ассемблера.**
    *   **Суть:** Мнемонические обозначения машинных команд (например, `MOV`, `ADD` вместо чисел). Требуют транслятора (ассемблера) для перевода в машинный код.
    *   **Особенности:** Чуть понятнее для человека, все еще низкоуровневые, используются для драйверов и критичных к скорости участков кода.
3.  **Третье поколение (3GL): Высокоуровневые процедурные языки.**
    *   **Суть:** Языки, приближенные к человеческому мышлению и математике. Код не привязан к железу напрямую.
    *   **Примеры:** Fortran, COBOL, C, Pascal, Java, Python.
    *   **Особенности:** Появились переменные, циклы, функции. Один оператор на таком языке заменяет несколько машинных команд. Главное достижение — переносимость (код можно скомпилировать на разных машинах).
4.  **Четвертое поколение (4GL): Языки сверхвысокого уровня / Декларативные.**
    *   **Суть:** Направлены на то, *что* нужно сделать, а не *как*. Ориентированы на конкретные предметные области (базы данных, интерфейсы).
    *   **Примеры:** SQL (запросы к базам данных), MATLAB (математика), языки отчетов.
    *   **Особенности:** Максимальное упрощение: программист описывает результат, а система сама решает, как его достичь.
5.  **Пятое поколение (5GL): Языки искусственного интеллекта и логического программирования.**
    *   **Суть:** Позволяют описывать не алгоритмы, а условия задачи и ограничения.
    *   **Примеры:** Prolog, Lisp, а также современные библиотеки машинного обучения (TensorFlow, PyTorch).
    *   **Особенности:** Система сама ищет решение на основе базы знаний и правил логического вывода. Используются для создания экспертных систем и нейросетей.

#### 3. Разница между языками низкого и высокого уровня

Главное различие — в степени близости к аппаратному обеспечению (железу) и удобстве для человека.

*   **Языки низкого уровня:**
    *   **Близость к машине:** Максимальная. Программист управляет регистрами процессора и ячейками памяти напрямую.
    *   **Скорость:** Максимальная, так как нет лишних прослоек.
    *   **Сложность:** Очень высокая. Нужно знать архитектуру процессора.
    *   **Переносимость:** Отсутствует (программа для Intel не пойдет на ARM без переписывания).
    *   **Примеры:** Машинный код (0 и 1), Ассемблер.

*   **Языки высокого уровня:**
    *   **Близость к машине:** Минимальная. Программист работает с абстракциями (объектами, списками, строками).
    *   **Скорость:** Чуть ниже (зависит от компилятора/интерпретатора, но современные оптимизаторы сводят разрыв к минимуму).
    *   **Сложность:** Низкая. Легко читать, писать и поддерживать. Похожи на английский язык.
    *   **Переносимость:** Высокая. Код, написанный на Python или Java, будет работать на Windows, Linux и MacOS без изменений (или с минимальными правками).
    *   **Примеры:** Python, Java, C++, C#, JavaScript, Go.

#### 4. Парадигмы программирования

**Парадигма программирования** — это стиль, философия или подход к написанию программного кода и решению задач. Это способ мышления о том, как должна быть организована программа.

**Основные парадигмы:**

1.  **Процедурная (Императивная):**
    *   **Суть:** Программа состоит из последовательности инструкций, которые изменяют состояние системы, и набора функций (процедур), которые эти инструкции группируют.
    *   **Подход:** «Сделай это, потом сделай то, потом повтори это 10 раз».
    *   **Примеры языков:** C, Pascal, Fortran, Basic.
    *   **Мир:** Готовка по рецепту (шаг за шагом).

2.  **Объектно-ориентированная (ООП):**
    *   **Суть:** Программа представляет собой совокупность объектов. Объект содержит данные (свойства/атрибуты) и методы (функции) для работы с этими данными. Основные принципы: инкапсуляция, наследование, полиморфизм.
    *   **Подход:** Моделирование реальных сущностей.
    *   **Примеры языков:** Java, C++, C#, Python, Ruby.
    *   **Мир:** Автомобиль (объект) имеет свойства (цвет, скорость) и методы (ехать, тормозить).

3.  **Функциональная:**
    *   **Суть:** Вычисления рассматриваются как вычисление математических функций. Основной упор делается на то, *что* вычислить, а не *как*. Ключевые черты: отсутствие изменяемых состояний (данные неизменяемы) и отсутствие побочных эффектов.
    *   **Подход:** Композиция чистых функций.
    *   **Примеры языков:** Haskell, Lisp, Erlang, F#, Scala (мультипарадигменный).
    *   **Мир:** Конвейер на заводе: данные входят, преобразуются функцией, выходят. Оригинальные данные не меняются.

4.  **Логическая (Декларативная):**
    *   **Суть:** Программа описывает правила, факты и отношения между объектами. Программист не пишет алгоритм решения, он задает условия, а система сама ищет решение.
    *   **Подход:** «Я знаю, что Джон — человек, а все люди смертны. Смертен ли Джон?».
    *   **Примеры языков:** Prolog, Datalog, SQL (частично).
    *   **Мир:** Разгадывание кроссворда или судоку: вы знаете правила, но не диктуете руке, куда ставить каждую цифру — ответ выводится из правил.

#### 2. Лучшие языки для начинающих

==У меня смешанное мнение на этот счёт! Будет устный ответ!==

Выбор первого языка — во многом вопрос личных целей, но существуют общепризнанные фавориты для новичков.

**Безусловный лидер — Python.**

*   **Почему:** Его синтаксис настолько близок к псевдокоду (описанию алгоритма словами), что программист учится решать задачу, а не бороться с особенностями языка. Минимум обязательных конструкций, отступы вместо фигурных скобок делают код читаемым даже у новичка.
*   **Плюсы:** Огромное обучающее комьюнити, тысячи библиотек на все случаи жизни, возможность быстро увидеть результат (написать игру, скрипт или график). Идеален для старта в Data Science и автоматизации.

**Второй претендент — JavaScript (для тех, кто хочет в веб).**

*   **Почему:** Результат виден мгновенно — открыл браузер, нажал F12, написал код, и он сразу выполняется. Не нужно устанавливать сложные среды разработки.
*   **Плюсы:** Это единственный язык фронтенда, а с Node.js и бэкенда. Спрос на рынке огромен. Недостаток: язык имеет много исторических странностей, которые могут сбить с толку на старте (например, нестрогое сравнение `==`).

**Третий вариант — Scratch (для детей и абсолютных нулевиков).**

*   Визуальная среда, где программы собираются из блоков, как конструктор. Это не «настоящий» язык для трудоустройства, но он великолепно ставит алгоритмическое мышление без страха перед ошибками синтаксиса.

**Вывод:** Я рекомендую **Python**. Он даёт прочную базу, не ограничивает будущий выбор (после него легко перейти на Java, C++ или JavaScript), и с ним можно заниматься как вебом, так и наукой о данных.

#### 3. Декларативные и императивные языки программирования

Эти два подхода отвечают на разные вопросы: **как** сделать (императивный) или **что** нужно получить (декларативный).

**Императивный подход (Как?)**

*   **Суть:** Программист описывает точную последовательность шагов, которые компьютер должен выполнить для достижения результата. Управляет состоянием программы: создаёт переменные, изменяет их значения, использует циклы и условия.
*   **Аналогия:** Вы звоните другу и говорите: «Выйди из дома, поверни налево, пройди 200 метров до магазина, зайди внутрь, найди отдел с хлебом...». Вы управляете каждым его движением.
*   **Примеры языков:** C, C++, Java, Python (в основном), JavaScript, Pascal.

**Декларативный подход (Что?)**

*   **Суть:** Программист описывает желаемый результат или свойства этого результата, а система сама определяет, как его достичь. Внимание сосредоточено на логике и данных, а не на пошаговом управлении.
*   **Аналогия:** Вы говорите другу: «Я хочу свежий хлеб из ближайшего магазина». Как он туда доберётся — не ваша забота.
*   **Примеры языков:** SQL (вы пишете `SELECT * FROM users WHERE age > 18`, а СУБД сама решает, какие индексы использовать и как обойти таблицы), HTML (описываете структуру, а не алгоритм отрисовки), CSS, регулярные выражения, а также функциональные языки вроде Haskell (частично).

**Ключевые отличия:**

| Критерий | Императивный | Декларативный |
| :--- | :--- | :--- |
| **Основной вопрос** | Как выполнить задачу? | Что должно быть результатом? |
| **Состояние** | Активно изменяется | Обычно неизменяемо или скрыто |
| **Порядок выполнения** | Строго задан | Определяется системой |
| **Уровень абстракции** | Ближе к машине | Ближе к человеку |
| **Сложность контроля** | Полный контроль, но больше кода | Меньше кода, меньше контроля над деталями |

**Пример для наглядности:**

*Задача: Найти все чётные числа в списке.*

*   **Императивно (Python):**
```python
result = []
for num in [1, 2, 3, 4, 5, 6]:
	if num % 2 == 0:
		result.append(num)
```

*   **Декларативно (SQL — если бы данные были в таблице):**
```sql
SELECT number FROM list WHERE number % 2 = 0;
```

Мы не указали, *как* проверить каждое число, мы просто сформулировали условие.

На практике многие языки смешивают парадигмы: Python в основном императивный, но имеет функциональные инструменты (list comprehensions, map/filter), которые делают код более декларативным.
### Стандарты и среды разработки

#### 1. Стандарт языка программирования: спецификация, синтаксис, семантика и зачем нужна стандартизация

**Стандарт языка программирования** — это официальный документ (обычно выпускаемый организацией по стандартизации, например ISO, ANSI, ECMA), который точно описывает, как должен работать язык: какие конструкции допустимы, как они должны интерпретироваться, какие правила преобразования типов и поведения программы гарантируются.

**Спецификация** — это сам текст стандарта, детальное техническое описание языка. Она служит эталоном для разработчиков компиляторов, интерпретаторов и программистов.

**Синтаксис** — это правила написания кода: из каких символов и в каком порядке могут состоять допустимые выражения, операторы, объявления. Это форма, «грамматика» языка. Например, в Python блок кода выделяется отступами, в C — фигурными скобками.

**Семантика** — это смысл написанного: что означает каждая конструкция, как она выполняется, каков результат. Семантика определяет поведение программы. Например, оператор `+` может означать сложение чисел, конкатенацию строк или объединение списков — это семантические правила.

**Зачем нужна стандартизация:**
1. **Переносимость:** Код, написанный по стандарту, должен одинаково работать в разных компиляторах или интерпретаторах (например, C++ код компилируется и в GCC, и в MSVC, если он соответствует стандарту).
2. **Совместимость:** Стандарт гарантирует, что программы, написанные для одной версии языка, будут предсказуемо работать и в будущих версиях (с оговорками на deprecation).
3. **Единое понимание:** Программисты и разработчики инструментов имеют общую точку отсчёта, избегая «диалектных» расхождений.
4. **Надёжность:** Стандарт фиксирует поведение, которое можно тестировать, снижая количество неопределённого поведения (undefined behavior).

#### 2. Определение IDE и её основные компоненты

**IDE (Integrated Development Environment)** — интегрированная среда разработки, комплексное программное обеспечение, объединяющее в одном приложении инструменты для написания, тестирования и отладки кода. Цель IDE — повысить производительность разработчика, автоматизировав рутинные операции и предоставив удобный интерфейс.

**Основные компоненты (3 ключевых):**

1. **Редактор кода (Code Editor).**
   *   **Функция:** Написание и редактирование исходного кода. Современный редактор включает подсветку синтаксиса, автодополнение (IntelliSense), проверку ошибок «на лету», навигацию по коду (переход к определению, поиск использований), рефакторинг. Это основной инструмент, с которым программист взаимодействует большую часть времени.

2. **Компилятор / Интерпретатор (Compiler / Interpreter).**
   *   **Функция:** Преобразование исходного кода в исполняемую форму (машинный код, байт-код) или непосредственное выполнение (в случае интерпретатора). IDE интегрирует вызов компилятора/интерпретатора, собирает проект (build), управляет зависимостями и показывает ошибки компиляции в удобном виде. Без этого компонента IDE была бы просто текстовым редактором.

3. **Отладчик (Debugger).**
   *   **Функция:** Поиск и исправление ошибок в логике программы. Позволяет запускать код пошагово, устанавливать точки останова (breakpoints), просматривать значения переменных в текущий момент, анализировать стек вызовов. Отладчик помогает понять, почему программа ведёт себя не так, как задумано.

*Дополнительно в IDE часто входят:* система контроля версий (Git), профилировщик производительности, визуальный конструктор интерфейсов, встроенный терминал, инструменты для работы с базами данных.

### Компиляторы и интерпретаторы. Жизненный цикл

#### 1. Компилятор и интерпретатор: определения, отличия, плюсы и минусы

**Компилятор** — это программа, которая переводит исходный код, написанный на языке программирования, целиком в машинный код (или промежуточное представление, например байт-код) до начала выполнения. На выходе получается отдельный исполняемый файл (`.exe`, `.class`, `.o`), который затем может запускаться без участия компилятора.

**Интерпретатор** — это программа, которая выполняет исходный код построчно (или поблочно) непосредственно во время работы, без создания отдельного исполняемого файла. Интерпретатор читает, анализирует и сразу исполняет каждую инструкцию.

**Принципиальная разница:**  
Компилятор работает **до** запуска программы (вся трансляция выполняется заранее), интерпретатор работает **во время** выполнения (трансляция и исполнение совмещены). Это приводит к различиям в скорости, гибкости и распространении программ.

**Плюсы и минусы:**

| Подход | Плюсы | Минусы |
| :--- | :--- | :--- |
| **Компилятор** | Высокая скорость выполнения (машинный код оптимизирован); исходный код не требуется для запуска (защита интеллектуальной собственности); возможна глубокая оптимизация на этапе компиляции | Более длительный цикл разработки (компиляция перед каждым запуском); программа привязана к конкретной платформе (нужна перекомпиляция под другую ОС/архитектуру); сложнее отладка (ошибки видны после компиляции) |
| **Интерпретатор** | Мгновенный запуск без отдельного шага компиляции; кроссплатформенность (если есть интерпретатор под нужную ОС, код работает везде); удобство отладки (ошибки видны сразу в месте выполнения); динамическая типизация (больше гибкости) | Более низкая скорость выполнения (интерпретация на лету); для запуска требуется наличие интерпретатора у пользователя; исходный код открыт (сложнее скрыть реализацию) |

**Когда что выбрать:**
- **Компилятор** предпочтителен, когда нужна максимальная производительность, ресурсоёмкие вычисления (игры, системное ПО, драйверы, высоконагруженные серверы) или когда нужно распространять программу без исходников.
- **Интерпретатор** удобен для быстрой разработки, прототипирования, скриптов автоматизации, веб-приложений, где скорость выполнения не критична, а скорость разработки важна.

**Примеры языков:**
- **Компилируемые:** C, C++, Go, Rust, Haskell (в чистый машинный код).
- **Интерпретируемые:** Python, Ruby, PHP, JavaScript (традиционно).
- **Гибридные (компиляция в байт-код + интерпретация/ JIT):** Java, C#, Python (в реализации CPython тоже компилирует в байт-код, который потом интерпретируется, но часто относят к интерпретируемым).

#### 2. Жизненный цикл программы: определение, зачем нужен, общая схема

[[1. Введение в управление IT-проектами#^f31155]]

**Жизненный цикл программы (ЖЦ)** — это период времени от появления идеи о создании программного продукта до его полного вывода из эксплуатации. Он включает все этапы: анализ требований, проектирование, разработку, тестирование, внедрение, сопровождение и утилизацию.

**Зачем нужен:**
1. **Управляемость:** Позволяет планировать ресурсы, сроки, бюджет.
2. **Качество:** Чёткое следование этапам снижает количество ошибок и повышает надёжность.
3. **Предсказуемость:** Стандартизированный процесс делает результат более предсказуемым.
4. **Контроль:** Упрощает отслеживание прогресса и внесение изменений.
5. **Сопровождение:** Обеспечивает поддержку и развитие продукта после выпуска.

**Общая схема жизненного цикла (от идеи до вывода из эксплуатации):**

```
[Идея/Потребность]
        ↓
[Анализ требований] → (Что нужно? Функции, ограничения)
        ↓
[Проектирование] → (Архитектура, структура данных, интерфейсы)
        ↓
[Разработка (кодирование)] → (Написание кода, модулей)
        ↓
[Тестирование] → (Поиск ошибок, проверка соответствия)
        ↓
[Внедрение (развёртывание)] → (Установка, настройка у пользователя)
        ↓
[Сопровождение] → (Исправление ошибок, обновления, доработки)
        ↓
[Вывод из эксплуатации] → (Прекращение поддержки, замена, удаление)
```

На практике этапы могут повторяться (итерации) или перекрываться.

#### 3. Основные модели жизненного цикла

[[2. Жёсткие и гибкие методологии]]

Существует несколько классических моделей организации процесса разработки. Основные:

1. **Каскадная (водопадная) модель (Waterfall)**
   - **Описание:** Строго последовательное выполнение этапов: сначала завершается анализ, потом проектирование, затем разработка и т.д. Переход к следующему этапу только после полного окончания предыдущего. Возврат на предыдущие этапы затруднён или запрещён.
   - **Плюсы:** Простота, понятность, чёткая документация, лёгкость управления.
   - **Минусы:** Низкая гибкость — любые изменения требований в середине процесса болезненны, тестирование откладывается на конец, высокий риск получения не того продукта.
   - **Когда применять:** Когда требования стабильны и точно определены (например, проекты с жёстким регулированием, оборонная промышленность, строительство).

2. **Инкрементная модель**
   - **Описание:** Разработка ведётся частями (инкрементами). Сначала выпускается базовая версия с ограниченным функционалом, затем к ней добавляются новые возможности. Каждый инкремент проходит полный цикл (анализ, проектирование, кодирование, тестирование).
   - **Плюсы:** Ранняя обратная связь от пользователя, возможность корректировать направление, снижение рисков.
   - **Минусы:** Сложнее проектировать общую архитектуру, так как она развивается постепенно, возможна фрагментация.
   - **Когда применять:** Когда продукт можно разбить на логические части, и важна быстрая поставка.

3. **Итеративная (эволюционная) модель**
   - **Описание:** Весь проект разбивается на повторяющиеся циклы (итерации). В каждой итерации создаётся рабочая версия продукта (не обязательно полнофункциональная), которая затем улучшается. Похожа на инкрементную, но здесь каждая итерация может уточнять требования и перепроектировать.
   - **Плюсы:** Гибкость, адаптация к меняющимся требованиям, постоянная обратная связь.
   - **Минусы:** Сложно оценить сроки и бюджет, риск «расползания» проекта.
   - **Когда применять:** Когда требования неясны или часто меняются, стартапы, исследовательские проекты.

4. **Спиральная модель**
   - **Описание:** Сочетание идей каскадной и итеративной моделей. Каждый виток спирали — это этап (анализ рисков, прототипирование, разработка, тестирование). Особое внимание уделяется анализу рисков. Витки повторяются до достижения целей.
   - **Плюсы:** Управление рисками, возможность раннего обнаружения проблем, гибкость.
   - **Минусы:** Сложность и высокая стоимость, требует высокой квалификации команды.
   - **Когда применять:** Крупные дорогостоящие проекты с высокими рисками (например, банковские системы, аэрокосмическая отрасль).

5. **V-образная модель**
   - **Описание:** Разновидность каскадной, где акцент на тестирование. Каждому этапу разработки соответствует этап тестирования. Левая часть V — спецификация и проектирование, правая — тестирование и интеграция.
   - **Плюсы:** Хорошая проверка качества, строгая дисциплина.
   - **Минусы:** Низкая гибкость, трудоёмкость.
   - **Когда применять:** Проекты с высокими требованиями к надёжности (медицина, авионика).

6. **Гибкие (Agile) методологии (Scrum, Kanban, XP)**
   - **Описание:** Не столько модель ЖЦ, сколько философия разработки. Характерны короткие итерации (спринты по 1–4 недели), тесное взаимодействие с заказчиком, постоянная доставка работающего функционала, самоорганизующиеся команды.
   - **Плюсы:** Максимальная адаптивность, высокая скорость выпуска, ориентация на потребности пользователя.
   - **Минусы:** Требует высокой вовлечённости заказчика, сложно предсказать конечный результат, может страдать документация.
   - **Когда применять:** Большинство современных коммерческих проектов, особенно веб-разработка и стартапы.

**Какие модели чаще всего применяются на практике и почему?**

На практике сегодня доминируют **гибкие методологии (Agile, Scrum, Kanban)** и **итеративно-инкрементные подходы**, часто в сочетании с элементами других моделей. Причины:

- **Быстрое изменение требований:** Рынок и технологии быстро меняются, заказчики хотят видеть результат как можно раньше и иметь возможность вносить изменения.
- **Снижение рисков:** Регулярная поставка работающего функционала позволяет выявлять проблемы на ранних стадиях.
- **Ориентация на пользователя:** Постоянная обратная связь гарантирует, что продукт соответствует реальным потребностям.
- **Экономическая эффективность:** Меньше вероятность потратить ресурсы на ненужные функции.

Каскадная и V-образная модели всё ещё применяются в областях с жёсткими стандартами и предсказуемыми требованиями (например, военная промышленность, медицинское оборудование, авионика), где любые изменения дорогостоящи, а безопасность критична. Но в основной массе коммерческой и веб-разработки гибкие подходы заняли лидирующие позиции.
### Программа и программный продукт

#### 1. Отличие понятия «программа» от «программного продукта»

**Программа (как набор инструкций)** — это последовательность команд, написанных на языке программирования, предназначенных для выполнения компьютером определённой задачи. Это технический артефакт: исходный код, исполняемый файл или скрипт.

**Программный продукт** — это завершённый, готовый к использованию комплекс, который включает в себя не только саму программу (исполняемый код), но и всю сопутствующую документацию, руководства пользователя, систему установки, гарантийные обязательства, лицензии и техническую поддержку. По сути, это «товар» или «решение», готовое для распространения и эксплуатации конечным пользователем.

**Ключевые отличия:**

| Критерий | Программа | Программный продукт |
| :--- | :--- | :--- |
| **Состав** | Только код (инструкции) | Код + документация + инсталлятор + поддержка + лицензия |
| **Цель создания** | Решить конкретную задачу для автора или узкого круга | Удовлетворить потребности широкого круга пользователей |
| **Уровень готовности** | Может быть «сырой», экспериментальной | Должен быть протестирован, стабилен, задокументирован |
| **Ответственность** | Автор не несёт обязательств перед другими | Производитель отвечает за работоспособность, обновления, безопасность |
| **Коммерческая ценность** | Обычно отсутствует (если не продаётся отдельно) | Является товаром или услугой, имеет рыночную стоимость |
| **Жизненный цикл** | Короткий: написал — запустил — забыл | Длительный: разработка → тестирование → выпуск → сопровождение → вывод |
| **Пример** | Скрипт для переименования файлов на своём ПК | Microsoft Word, Adobe Photoshop, мобильное приложение в App Store |

Таким образом, программный продукт — это эволюция программы: она «упакована», проверена, документирована и превращена в продукт, готовый к массовому использованию.

#### 2. Качество программного продукта, ISO и характеристики по ISO 25010

**Качество программного продукта** — это степень, в которой программный продукт удовлетворяет заявленные и подразумеваемые потребности пользователей и заинтересованных сторон при использовании в заданных условиях. Это совокупность свойств, определяющих его пригодность, надёжность, удобство и эффективность.

**ISO (International Organization for Standardization)** — Международная организация по стандартизации, основанная в 1947 году. Её главная задача — разработка и публикация международных стандартов в различных областях (техника, технологии, управление, экология и др.), обеспечивающих совместимость, безопасность и качество продукции и услуг. В сфере программного обеспечения ISO выпускает стандарты, которые задают единые критерии оценки и требования к процессам разработки и характеристикам продуктов.

**Стандарт ISO 25010** (Systems and software engineering — Systems and software Quality Requirements and Evaluation) — это актуальная модель качества программного продукта, заменившая устаревший ISO 9126. Она определяет две группы характеристик: **качество в использовании** (как продукт воспринимается конечным пользователем в реальных условиях) и **качество самого продукта** (внутренние и внешние свойства).

**Схема ключевых характеристик качества программного продукта по ISO 25010:**

---

#### А. Качество в использовании (Quality in Use)

*   **Результативность (Effectiveness):** точность и полнота, с которой пользователи достигают поставленных целей.
*   **Эффективность (Efficiency):** соотношение затраченных ресурсов (время, усилия, финансы) к достигнутому результату.
*   **Удовлетворённость (Satisfaction):** степень комфорта, положительного отношения и отсутствия дискомфорта при использовании.
*   **Свобода от риска (Freedom from risk):** минимизация потенциальных негативных последствий для пользователя, бизнеса или окружающей среды.
*   **Покрытие контекста (Context coverage):** способность продукта эффективно работать в различных условиях использования (устройства, сети, культурные особенности).

---

#### Б. Качество продукта (Product Quality)

*   **Функциональная пригодность (Functional Suitability):** насколько набор функций соответствует потребностям пользователей.
    *   *Функциональная полнота* — все ли необходимые задачи покрыты.
    *   *Функциональная корректность* — правильны ли результаты.
    *   *Функциональная целесообразность* — нет ли лишних, вводящих в заблуждение функций.
*   **Производительность (Performance Efficiency):** эффективность использования ресурсов.
    *   *Время отклика* — быстрота реакции.
    *   *Пропускная способность* — объём обрабатываемых данных за единицу времени.
    *   *Использование ресурсов* — насколько экономно расходуются память и процессор.
*   **Совместимость (Compatibility):** способность продукта работать с другими системами.
    *   *Сосуществование* — без конфликтов на одной платформе.
    *   *Интероперабельность* — возможность обмена данными и услугами.
*   **Удобство использования (Usability):** насколько продукт понятен и удобен для пользователя.
    *   *Понятность* — лёгкость изучения.
    *   *Обучаемость* — быстрота освоения.
    *   *Управляемость* — контроль над действиями.
    *   *Защита от ошибок* — предотвращение неверных действий.
    *   *Эстетика интерфейса* — визуальная привлекательность.
*   **Надёжность (Reliability):** способность работать без сбоев в течение заданного периода.
    *   *Завершённость* — устойчивость к отказам.
    *   *Отказоустойчивость* — сохранение работы при сбоях.
    *   *Восстанавливаемость* — скорость восстановления после отказа.
*   **Безопасность (Security):** защита информации от несанкционированного доступа.
    *   *Конфиденциальность* — доступ только авторизованным.
    *   *Целостность* — защита от несанкционированных изменений.
    *   *Неотказуемость* — доказательность действий.
    *   *Подотчётность* — отслеживание действий пользователей.
*   **Сопровождаемость (Maintainability):** лёгкость внесения изменений и исправлений.
    *   *Модульность* — разделение на независимые части.
    *   *Повторная используемость* — возможность переиспользования компонентов.
    *   *Анализируемость* — лёгкость поиска причин дефектов.
    *   *Изменяемость* — простота модификации кода.
    *   *Тестируемость* — удобство проверки после изменений.
*   **Переносимость (Portability):** способность работать на разных платформах.
    *   *Адаптируемость* — приспособление к новым условиям без доработки.
    *   *Устанавливаемость* — простота установки.
    *   *Заменяемость* — возможность замены другого продукта.

---

**Итог:** Стандарт ISO 25010 предоставляет структурированную систему критериев, которая позволяет объективно оценивать программный продукт с точки зрения как технических характеристик, так и пользовательского опыта. Это особенно важно при выборе готового ПО, разработке требований и проведении сертификации.

### Этапы решения задач на компьютере

#### 1. Классическая цепочка решения задачи с помощью ЭВМ

Решение задачи на компьютере — это не просто написание кода, а последовательный процесс преобразования исходной проблемы в работающую программу. Классическая цепочка включает следующие этапы:

1. **Постановка задачи**
   Формулируется, что дано и что требуется получить. Определяются исходные данные, результаты, ограничения и критерии успеха. Строится математическая или содержательная модель задачи.

2. **Анализ и выбор метода решения**  
   Изучаются возможные подходы (алгоритмы, формулы, численные методы). Выбирается наиболее подходящий с учётом точности, скорости, доступных ресурсов.

3. **Разработка алгоритма**  
   Создаётся точное предписание (алгоритм), описывающее последовательность действий для получения результата. Алгоритм может быть записан в виде блок-схемы, псевдокода или словесного описания.

4. **Программирование (кодирование)**  
   Алгоритм переводится на конкретный язык программирования. Пишется исходный код программы.

5. **Отладка и тестирование**  
   Программа проверяется на наличие ошибок (отладка) и на соответствие требованиям (тестирование). Выполняются запуски на тестовых данных, исправляются дефекты.

6. **Документирование**  
   Составляются описания программы: инструкция пользователя, техническая документация, комментарии в коде.

7. **Внедрение и сопровождение**  
   Программа передаётся пользователям, при необходимости обновляется и дорабатывается.

---

**Самый важный и трудоёмкий этап** — **постановка задачи и разработка алгоритма** (часто объединяют как «проектирование»).  

**Почему:**
- **Ошибки на ранних этапах стоят дороже всего.** Если неверно понята задача или выбран неэффективный алгоритм, весь последующий труд может оказаться напрасным. Исправление ошибки в постановке на этапе тестирования может потребовать полной переделки.
- **Трудоёмкость.** Алгоритмизация требует глубокого анализа, творческого мышления и учёта множества факторов. Написание кода по готовому алгоритму часто механическая работа, тогда как создание алгоритма — интеллектуальная.
- **Влияние на качество.** Правильно выбранный алгоритм может радикально сократить время выполнения и потребление памяти (например, выбор между линейным поиском и бинарным).  

Таким образом, именно на этапе постановки и алгоритмизации закладывается фундамент успеха всего проекта.

---

#### 2. Тестирование и отладка

**Тестирование** — это процесс проверки программы с целью обнаружения ошибок (дефектов) и подтверждения соответствия требованиям.  
**Отладка** — это процесс поиска, локализации и исправления уже обнаруженных ошибок.

**Таблица сравнения:**

| Параметр | Тестирование | Отладка |
| :--- | :--- | :--- |
| **Что такое** | Систематический процесс выполнения программы на наборах входных данных для выявления несоответствий ожидаемому поведению | Процесс анализа и устранения причин уже найденных дефектов |
| **Цель** | Обнаружить как можно больше ошибок, убедиться в работоспособности | Найти источник ошибки и исправить её, восстановить работоспособность |
| **Что делает** | Запускает программу с тестовыми данными, сравнивает фактические результаты с ожидаемыми, фиксирует отклонения | Исследует код, использует точки останова, трассировку, просмотр переменных, вносит исправления |
| **Кто выполняет** | Тестировщик (отдельный специалист) или сам разработчик; может быть автоматизированное тестирование | Обычно сам разработчик, так как требуется глубокое понимание кода |
| **Какой результат** | Отчёт об ошибках (баг-репорты), подтверждение качества или список дефектов | Исправленный код, устранённая ошибка, обновлённая версия программы |

**Разница между процессами:**
- **Направленность:** тестирование направлено на *выявление* ошибок, отладка — на *исправление*.  
- **Исполнители:** тестирование может выполняться отдельной командой, отладка — автор кода.  
- **Используемые методы:** тестирование использует тест-планы, тест-кейсы, автоматизацию; отладка — инструменты разработчика (debugger, логи).  
- **Результат:** тестирование даёт информацию о наличии проблем, отладка — конкретное изменение кода.  

Оба процесса тесно связаны: после отладки требуется повторное тестирование (регрессионное), чтобы убедиться, что исправление не внесло новых ошибок.
### Типы данных

#### 1. Определение «Тип данных» и его характеристики

**Тип данных** — это классификация данных, определяющая:
- множество допустимых значений;
- способ хранения в памяти (объём и представление);
- набор операций, которые можно выполнять над этими данными;
- правила преобразования к другим типам.

Тип данных позволяет компилятору или интерпретатору контролировать корректность операций (например, предотвращать сложение числа и строки) и оптимизировать использование памяти.

**Основные характеристики, которые определяет тип данных:**
1. **Допустимые значения** — какие данные можно хранить (например, целые числа от -2^31 до 2^31-1 для `int`).
2. **Объем памяти** — сколько байт требуется для хранения значения (например, `int` обычно 4 байта, `char` — 1 байт).
3. **Операции** — какие действия разрешены (сложение, сравнение, конкатенация и т.д.).
4. **Способ представления** — как значение кодируется в двоичном виде (целые — дополнительный код, вещественные — IEEE 754, символы — коды таблицы символов).
5. **Правила преобразования** — как значение преобразуется в значение другого типа (явное/неявное приведение).

---

#### 2. Базовые (примитивные) типы данных (5 основных)

В большинстве языков программирования выделяют следующие базовые типы:

1. **Целочисленный** (integer) — целые числа.
2. **Вещественный** (float/double) — числа с плавающей точкой.
3. **Символьный** (char) — одиночный символ.
4. **Логический** (boolean) — истина/ложь.
5. **Строковый** (string) — последовательность символов (в некоторых языках является примитивным, в других — составным, но часто включается в базовые).

В ряде классификаций вместо строкового указывают **указатель** или **пустой тип (void)**, но для учебных целей строковый тип удобен как базовый.

---

#### 3. Сравнительная таблица базовых типов данных

| Тип | Что хранит | Диапазон значений | Объем памяти | Основные допустимые операции | Основные недопустимые операции | Способ представления в памяти | Правила преобразования |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Целочисленный (int)** | Целые числа (0, -5, 42) | Зависит от размера: для 32-битного int: от -2 147 483 648 до 2 147 483 647 | Обычно 2 или 4 байта (зависит от языка/платформы) | Сложение, вычитание, умножение, деление (целочисленное), остаток, сравнения, побитовые операции | Деление на ноль, извлечение квадратного корня (без приведения), операции с плавающей точкой без явного преобразования | Двоичный дополнительный код (для отрицательных чисел) | Неявно преобразуется в вещественный при смешанных операциях; при переполнении возможен сброс или исключение |
| **Вещественный (float/double)** | Действительные числа (3.14, -0.001, 2.0) | Для double (64 бит): примерно от ±5.0×10^-324 до ±1.7×10^308, точность ~15 значащих цифр | float — 4 байта, double — 8 байт (обычно) | Арифметические операции, сравнения, математические функции (sin, sqrt и т.п.) | Побитовые операции, точное сравнение на равенство (из-за погрешностей) | Формат IEEE 754: знак + экспонента + мантисса | Может преобразовываться в целый с потерей дробной части; при переполнении — бесконечность/NaN |

| **Строковый (string)** | Последовательность символов (текст) | Ограничен объёмом памяти | Зависит от длины строки и кодировки: каждый символ 1–4 байта + служебная информация (длина, терминатор) | Конкатенация, извлечение подстроки, поиск, сравнение, изменение регистра, форматирование | Арифметические операции, побитовые операции | Последовательность байтов в определённой кодировке (ASCII, UTF-8, UTF-16) с терминатором (в C) или счётчиком длины | Может преобразовываться в число (если содержит цифры) или наоборот (число в строку); в некоторых языках строки неизменяемы |

*Примечание: диапазоны и размеры могут отличаться в зависимости от конкретного языка программирования и архитектуры процессора.*

---

#### 4. Производные типы данных и массивы

**Производные типы данных** — это типы, которые строятся на основе базовых (примитивных) или других производных типов с помощью специальных конструкций языка. Они позволяют группировать данные, создавать структуры для хранения коллекций и сложных объектов.

Примеры производных типов:
- **Массивы** — упорядоченные наборы элементов одного типа.
- **Структуры (struct)** — наборы полей разных типов, объединённых под одним именем.
- **Классы (class)** — как структуры, но с методами и инкапсуляцией.
- **Указатели** — хранят адреса памяти.
- **Ссылки** — альтернативный механизм доступа к данным.
- **Объединения (union)** — позволяют хранить разные типы в одной области памяти.
- **Перечисления (enum)** — набор именованных констант.

**Массив** — это структура данных, представляющая собой последовательность фиксированного (или динамического) числа элементов **одного типа**, расположенных в памяти подряд. Доступ к элементам осуществляется по индексу (обычно с нуля). Массивы позволяют эффективно хранить и обрабатывать множества однотипных данных (например, список оценок, координаты точек). Количество элементов может быть задано на этапе компиляции (статический массив) или во время выполнения (динамический массив).

---

#### 5. Структура (struct), класс (class) и метод: определения и отличия

**Структура (struct)** — это составной тип данных, объединяющий под одним именем несколько полей (переменных) произвольных типов. Обычно структуры используются для группировки логически связанных данных (например, точка с координатами x и y). В классическом понимании структуры не содержат методов (функций), хотя в некоторых языках (C++, C#) это разрешено.

**Класс (class)** — это более мощная конструкция, которая, помимо полей (данных), содержит **методы** (функции) для работы с этими данными. Классы являются основой объектно-ориентированного программирования (ООП): поддерживают инкапсуляцию (скрытие внутренней реализации), наследование и полиморфизм. Экземпляры класса называются объектами.

**Метод** — это функция, определённая внутри класса (или структуры, если язык это допускает) и предназначенная для работы с данными объекта. Метод имеет доступ к внутренним полям объекта через неявный указатель/ссылку (`this`/`self`). Методы определяют поведение объектов.

**Отличия:**

| Критерий | Структура (struct) | Класс (class) | Метод (method) |
| :--- | :--- | :--- | :--- |
| **Что это** | Составной тип данных | Составной тип + поведение | Функция внутри класса/структуры |
| **Содержит** | Обычно только поля (данные) | Поля и методы | Логику (код) |
| **Инкапсуляция** | Часто отсутствует или ограничена | Есть (private, protected, public) | Является средством инкапсуляции поведения |
| **Наследование** | Обычно не поддерживается | Поддерживается (в ООП) | Наследуется вместе с классом |
| **Память** | Обычно хранится по значению (стек или внутри другого объекта) | Обычно хранится по ссылке (куча) | Не занимает память отдельно — часть класса |
| **Пример** | `struct Point { int x; int y; };` | `class Car { int speed; void accelerate(); };` | `void accelerate() { speed += 10; }` |

*Примечание: в некоторых языках (C++) структуры и классы почти идентичны, различие лишь в уровне доступа по умолчанию (public у struct, private у class).*

#### 6. Перечисляемый тип (enum) и его назначение

**Перечисляемый тип (enum)** — это производный тип данных, который определяет множество именованных целочисленных констант. Он позволяет задать ограниченный набор возможных значений для переменной, например: дни недели, цвета, состояния.
**Для чего нужен:**
1. **Улучшение читаемости кода.** Вместо магических чисел (`if (day == 1)`) используются осмысленные имена (`if (day == MONDAY)`).
2. **Контроль допустимых значений.** Компилятор/интерпретатор может предупредить, если переменной присваивается значение, не входящее в перечисление.
3. **Упрощение рефакторинга.** Если нужно изменить числовое значение константы, достаточно изменить его в определении enum, а не искать по всему коду.
4. **Безопасность типов.** Переменная типа `enum` не может быть неявно смешана с целыми числами без явного приведения (в некоторых языках).

**Пример:**
```c
enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY };
enum Day today = WEDNESDAY;
```

По умолчанию значения присваиваются последовательно с нуля (MONDAY=0, TUESDAY=1 и т.д.), но можно задать свои числа: `enum Status { OK = 200, NOT_FOUND = 404, SERVER_ERROR = 500 };`.
